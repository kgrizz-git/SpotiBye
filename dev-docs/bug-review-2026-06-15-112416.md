# Deep Bug Review - 2026-06-15 11:24:16

Scope: whole-codebase review, not limited to recent changes. Focus areas were backend auth/API/export behavior, frontend API/client/export flows, edge cases around selections and formats, cache boundaries, and verification health.

## Findings

### High: Backend playlist detail and track cache keys are not user-scoped

`/spotify/playlists/:id` uses `playlist:${playlistId}` and `/spotify/playlists/:id/items` uses `playlist:${playlistId}:tracks:${limit}:${offset}` before calling Spotify. If one authorized user warms the cache for a private or collaborative playlist, another authenticated user who requests the same playlist ID can receive cached data without Spotify re-authorizing access for that user.

References:
- `src/backend/routes/spotify.ts:112`
- `src/backend/routes/spotify.ts:141`

### High: Export pagination can truncate or duplicate playlists with local/unavailable items

`SpotifyService.normalizePlaylistItemsResponse()` filters out entries without a track id, then export pagination uses the filtered item count to decide whether to stop and to advance offsets. A raw Spotify page with 100 items but 95 valid tracks can stop synchronous export early. The resumable path can advance by 95 instead of the raw page size and overlap the next request.

References:
- `src/backend/services/spotify.ts:74`
- `src/backend/services/export.ts:476`
- `src/backend/services/export.ts:312`

### High: User-selected export formats are silently ignored

The UI offers `XLSX`, `CSV`, and `JSON`, but the export worker forces `.xlsx`, sends `"xlsx"` to combined export endpoints, and the sequential fallback also writes `.xlsx`. The backend only treats `csv` specially, so `json` currently becomes XLSX.

References:
- `src/frontend/screens/main_screen.py:414`
- `src/frontend/screens/main_screen.py:1166`
- `src/frontend/screens/main_screen.py:1344`
- `src/frontend/screens/main_screen.py:1591`
- `src/backend/routes/export.ts:73`

### Medium: Playlist analysis only processes the first 100 tracks

`AnalysisService.analyzePlaylist()` calls `getPlaylistTracks(playlistId, 100, 0)` once and never paginates. Playlists over 100 tracks get partial totals, artist counts, genre distribution, and insights.

Reference:
- `src/backend/services/analysis.ts:62`

### Medium: Combined XLSX export can fail on duplicate worksheet names

Sheet names are sanitized and truncated, but not made unique. Two selected playlists with the same name/owner, or names that collide after 31-character truncation, can make `workbook.addWorksheet()` throw.

References:
- `src/backend/services/export.ts:589`
- `src/backend/services/export.ts:907`

### Medium: OAuth flow is documented as PKCE but implementation does not implement PKCE

The architecture and docs describe Spotify OAuth PKCE, but the frontend sends only `redirect_uri`; the backend stores only that URI; the Spotify auth URL has no `code_challenge`; token exchange has no `code_verifier`. This is a protocol/security mismatch and can break if Spotify enforces native-app PKCE expectations.

References:
- `src/frontend/services/backend_client.py:197`
- `src/backend/routes/auth.ts:14`
- `src/backend/services/spotify-auth.ts:22`
- `src/backend/services/spotify-auth.ts:50`

### Medium: Installed console script points to a removed package

`pyproject.toml` still exposes `spotify-playlist-exporter = "spotify_playlist_exporter_v2.__main__:main"`, while the code map says that legacy entrypoint and package were removed. A direct import check for `spotify_playlist_exporter_v2.__main__` fails with `ModuleNotFoundError`.

References:
- `pyproject.toml:33`
- `dev-docs/code-map.md:16`

### Medium: JWT signing falls back to a hardcoded default secret

`JWTService` uses `default-secret` when `JWT_SECRET` is missing. A misconfigured deployment would issue and accept predictable tokens instead of failing closed.

Reference:
- `src/backend/services/jwt.ts:22`

### Low: `CacheService.exists()` passes an invalid Cloudflare KV option shape

Workers types expect `{ type: "stream" }` or `"stream"`, but `exists()` passes `{ stream: true }` behind a cast. Tests assert the invalid shape, so production may report render modes as unavailable even when download bytes exist.

Reference:
- `src/backend/services/cache.ts:51`
