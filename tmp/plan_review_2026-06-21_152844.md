### 2. BT-4 `console.error` vs golden principle

**Location:** Plan line 80-83 — BT-4 steps

The golden principles in `AGENTS.md` state: *"No `console.log` in non-test backend code — use structured logging"*. The plan calls for `console.error()` which is technically a different function but the spirit of the principle (avoid bare console calls) likely applies.

**Impact:** Low/Medium. `console.error` is already used elsewhere in the codebase (e.g., `index.ts:79`), so this is consistent with existing patterns. However, for a "critical" security fix, it would be better to use the project's structured logger if one exists, or at minimum use a consistent format.

**Recommendation:** Check if the project has a structured logging utility (search for `pino`, `winston`, `log`, `logger`). If not, `console.error` is acceptable but note it as a minor deviation from best practices.
